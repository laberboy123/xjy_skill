# L0–L6 判据速查 + 常见坑

配合 `skills/sensor-bringup/SKILL.md` 使用。这里只放判据细节、坑位和平台命令，不重复流程说明。

## 逐层判据

| 层 | 一票否决项 | 定量判据 | 常用工具 |
|---|---|---|---|
| L0 | VDD-GND 短路、IO 电平不匹配、缺上拉 | 阻抗 kΩ 级；电压 ±5%；上拉按速率与电容核算 | 万用表、原理图 |
| L1 | 无 ACK、上升沿塌陷、SPI 模式错 | I2C 400k 上升时间 ≲300ns、100k ≲1µs；CS setup/hold 满足 datasheet | 逻辑分析仪、示波器 |
| L2 | 扫不到地址、ID 不符 | ID 与 datasheet 标称值逐位一致 | i2cdetect、probe 固件 |
| L3 | 回读不一致、reset 值不符 | 全部寄存器回读一致（除只写/状态位） | dump_regs |
| L4 | 数据恒定、不随激励变化 | 随激励单调；零点/噪声在规格内 | read_raw + 物理激励 |
| L5 | 异常后死等、需重启恢复 | 有超时；恢复 < 3s；1h 丢帧 0 | 故障注入 |
| L6 | 采样率不达标、时间戳漂移 | 8h 漂移在规格内；换算用已知量反算 | 应用固件 + 上位机 |

## I2C 常见坑

| 现象 | 常见原因 | 判据 |
|---|---|---|
| 扫不到地址 | ADDR 脚接法、器件未上电、总线被拉死 | 量 ADDR 电平；断电测 SDA/SCL 是否被拉低 |
| 扫到但不是预期地址 | 地址是 8 位写法（含 R/W 位）与 7 位混用 | 确认代码里用的是 7 位左移 |
| 读全 0xFF | 从机没应答，主机读到浮空 | 看 ACK 位是否被拉低 |
| 读全 0x00 | 总线被从机拉死（常见于通信中断） | SCL 打 9 个脉冲解锁后复测 |
| 偶发 NACK | 上拉过弱、总线电容大、线太长、速率过高 | 降速对照；量上升时间 |
| 只能读不能写 | 写保护脚、只写寄存器顺序错 | 查 WP 脚；查是否有 unlock 序列 |
| 多器件冲突 | 地址重复、共用总线无仲裁 | 逐个上电/逐个断开验证 |
| 上电首次读失败 | 器件上电时间不够（POR 需要 ms 级） | 加延时到 datasheet 的 tPOR 后复测 |

## SPI 常见坑

| 现象 | 常见原因 | 判据 |
|---|---|---|
| 读全 0xFF / 0x00 | MISO 浮空、CS 未拉低、从机未上电 | 示波器看 MISO 是否有驱动 |
| 数据错位 | CPOL/CPHA 不匹配（模式 0–3） | 逐个模式试，看 ID 是否出现 |
| 首字节丢失 | CS 建立时间不足 | 加 CS 前置延时 |
| 读写方向反 | 最高位是 R/W 位，地址只有 7 位 | 查 datasheet 的读写位定义 |
| 多字节读错位 | 地址不自增，或需要 burst 命令 | 查是否要发 0x80/0x40 类自增位 |
| 高速下不稳 | 时钟过快、走线长、无地回流 | 降频对照 |

## 平台命令速查

**Linux**

```bash
i2cdetect -y -r 1                 # 扫总线 1（-r 用 SMBus 读，避免误写）
i2cget -y 1 0x68 0x75             # 读寄存器
i2cset -y 1 0x68 0x75 0x00        # 写寄存器
i2cdump -y 1 0x68                 # 全量 dump（慎用，可能触发副作用）
ls /dev/spidev*                   # SPI 设备
dmesg | grep -i i2c               # 看总线错误/超时
```

**RT-Thread**

```c
/* 优先用消息结构，别自己拼时序 */
struct rt_i2c_msg msgs[2];
msgs[0].addr = addr; msgs[0].flags = RT_I2C_WR; msgs[0].buf = &reg; msgs[0].len = 1;
msgs[1].addr = addr; msgs[1].flags = RT_I2C_RD; msgs[1].buf = buf; msgs[1].len = len;
rt_i2c_transfer(bus, msgs, 2);   /* 返回传输的消息数，必须校验 */
```

msh 里先 `list_device` 确认设备注册，再看 `pin` 状态。

**FreeRTOS / 裸机**

- 先用 GPIO bit-bang 跑通一颗，确认波形、地址、时序，再换硬件外设。
- bit-bang 时注意：开漏输出要切换方向；SCL 高电平期间读 SDA；每个时钟后检查 ACK。
- 超时用计数器，不要 `while(!flag);`。

## 换料/换批次必做

1. dump reset 寄存器快照，与 datasheet reset value 逐项比对
2. 比对 ID/版本寄存器（很多器件 ID 相同但版本不同，寄存器映射有差异）
3. 重跑 L4（量程、ODR、零点可能变了）
4. 记录批次号进证据日志

## 高频"假通过"

| 假通过 | 真相 |
|---|---|
| 能读到 ID | 只证明 I2C/SPI 通了，不证明配置对、不证明数据对 |
| 数据有变化 | 可能是噪声在变，不是被测物理量在变（要做激励-响应相关性） |
| 测试跑通了 | 可能没测到异常路径 |
| 换了器件就好了 | 没找到根因，下一批还会回来 |
| 在同一块板上反复通过 | 缺第二块板/EVK 的交叉验证 |
