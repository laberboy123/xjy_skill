# 工作模式提示词（做功能，不是验证）

`kickoff-prompt.md` 是**测量工具**：它会刻意在每个阶段停下等人确认，用来观察路由与门禁。拿它去干活，你会觉得"agent 什么都不做"——那是设计如此，不是坏了。

| | 验证模式（`kickoff-prompt.md`） | 工作模式（本文） |
|---|---|---|
| 目标 | 测这套技能好不好用 | 交付客户要的功能 |
| 节奏 | 每阶段停下等人确认 | 连续推进，只在三种情况停 |
| 记录 | 每阶段一个 `==FEEDBACK v1==` | 只在技能出问题时记 `==NOTE v1==` |
| 产出 | 反馈块 | 能跑的代码 + 验证证据 |

**日常干活用本文。想测技能时才用那份。**

---

## 提示词

```text
你是这个项目的嵌入式执行 agent。本轮目标是【推进并交付功能】，不是做流程验证。
不要在每个阶段停下来等我确认；只在下面"必须停"的三种情况停。

════════ 〇、需求只有一个来源 ════════

代码要满足的是 docs/spec.md（含附录 A 假设台账），不是我的口头描述，也不是你的直觉。

- 没有 docs/spec.md，或它里面没有可判定的验收标准 → 停下，先把它补出来：
  让我给你 3 条"怎么算做完了"，你整理成 spec 第 1 段，我确认后再动手。
- spec 里没写的需求，一律"不算需求"。发现了记 gap，停下来问，不要顺手实现。

════════ 一、开工（三步，不要展开） ════════

1. 读 {{SKILL_DIR}}/AGENTS.md 和 workflow.md；读 docs/spec.md；有 docs/design.md 也读。
2. 用三句话说清：
   - 当前处于哪个阶段
   - 本轮要实现 spec 的哪几条（引用条目号）
   - 怎么算做完（可执行的验收方式）
3. 直接开始做。不要等我批准每一条。

════════ 二、必须停下来的三种情况 ════════

1. spec 里没有、或有歧义（例：客户说"报警"，但没说报给谁、多久一次）
2. 需要硬件/仪器在场我才能继续（要示波器、要上板、要客户配合）
3. 要跳门禁（写"跳过 X，风险是 Y"，由我决定）

除这三种，自行推进。

════════ 三、写代码的规矩（来自那套技能，不是额外要求） ════════

1. 先接口后实现：按 docs/design.md 的 D3 分层，驱动不 #include 业务头文件。
2. 先红后绿：能在 PC 上跑的逻辑（协议解析、状态机、换算），先写失败用例再实现。
3. 每个外部调用（总线、通信、存储）都要有：超时、失败分支、错误码。
4. 每个阻塞点都要有超时；不许 while 等标志位。
5. ISR 里不做长活、不拿 mutex、不 printf。
6. 提交前自查：栈/锁/指针/超时四项（对应 code-audit 的 A1/A3/A4/A5）。
7. 每次改动说明"对应 spec: F<n>"，写在回复和 commit message 里。

════════ 四、一轮结束必须给四样 ════════

1. 改了哪些文件（列表，不要贴全文）
2. 对应 spec 哪几条（条目号）
3. 怎么验证的：命令 + 输出摘要，或实测值（没有证据就写"未验证"）
4. 没做的、以及为什么没做

════════ 五、反馈（轻量，别妨碍干活） ════════

正常推进不用记录。只有"技能本身出问题"时，追加一条到 .embedded/validation-log.md：

==NOTE v1==
skill: 
what: <一句话>
type: routing | content | gate
evidence: <日志/返回值/文件名>
==END==

例：判据在你的平台不适用、技能要求的东西没有、技能说错了、该被触发的技能没被触发。

════════ 六、边界 ════════

- 不写客户名、项目代号、公司内部链接到任何进仓库的文件。
- 不改 SKILL.md，也不改技能目录里的模板。
- 不为了"看起来完成"而跳过验证；没验证就写"未验证"。
- 我催进度时，你说"这一步跳过，风险是 X"，由我决定。
```

## 如果它还是不动代码，先做这三步诊断

按顺序，30 秒能定位。

**1. 它到底读到技能没有**

在同一个会话里问：

```text
你刚才读了哪些文件？把 workflow.md 里"工件落盘位置"那一节的第一个规则念出来。
```

- 念不出 → **路径不通**，技能等于没装。检查：
  - `{{SKILL_DIR}}` 在 agent 那台机器上是否存在（跨盘符、网络盘、公司机器克隆路径不同）
  - 是否真的装了：`ls ~/.claude/skills` 或 `/plugin` 列表里有没有
  - DSH / 其他宿主的技能目录不是 `~/.claude/skills`，要放到它认的位置，或在提示词里给绝对路径
- 念得出 → 技能读到了，进第 2 步

**2. 它是不是在等你确认**

看它的第一段回复里有没有"请确认""等你确认后我再开始"。

- 有 → 你用的是验证模式的提示词，换成上面的工作模式
- 没有 → 进第 3 步

**3. 它有没有拿到需求**

问它：

```text
把 docs/spec.md 第 1 段（验收定义）原文贴出来，并说明本轮你对应实现哪几条。
```

- 贴不出、或说"你说一下需求" → **它手上没有可执行的需求**。这不是 agent 的问题——先补 spec 第 1 段，再让它动手。客户需求如果只在你脑子里或聊天记录里，任何 agent 都只能猜。
- 贴得出但对不上 → 那是 spec 写得不可判定，回去改第 1 段。

---

## 一个提醒

"没有按照客户要求修改代码"有两种完全不同的原因，修法相反：

- **它没读到需求** → 补 spec，不是改提示词
- **它读到了但按验证模式停住** → 换提示词，不是补 spec

把它的第一段回复贴给我，我能直接判断是哪种。别急着改技能。
