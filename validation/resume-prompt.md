# 新会话续接

新会话没有上一次的记忆。要让 agent 接上，靠三样东西，缺一样就会跑偏：

| 文件 | 作用 | 读法 |
|---|---|---|
| `docs/spec.md` | 应该做什么（意图） | 第 1 段验收 + 第 3 段功能清单 |
| 代码 + git | 实际做到哪（真相） | 以它为准，不以描述为准 |
| `.embedded/resume.md` | 索引：现状、下一步、未决 | 覆盖写，10 行以内 |
| `.embedded/validation-log.md` | 事件流（给技能维护用） | 只看最后 10 行 |

前两样本来就有。**`resume.md` 是缺的那一样**——它必须由上一个会话在收尾时写下，否则新会话只能靠猜。

---

## 续接提示词（新开会话第一句）

```text
继续这个项目。先不要写代码，按顺序做四件事：

1. 读 .embedded/resume.md。没有就直说，我们从零定位。
2. 读 docs/spec.md 的第 1 段和第 3 段（验收定义 + 功能清单）。
3. 读 .embedded/validation-log.md 的最后 10 行。
4. 用五句话说清，然后等我确认：
   - 现在处于哪个阶段，阶段内做到哪一步
   - 上一轮在做什么，做到什么程度
   - 下一步要做什么（具体到文件/函数/spec 条目号）
   - 有没有未决问题在等我决定
   - 有没有跟 resume.md 对不上的地方

对不上的处理规则：状态以代码和 git 为准，需求以 docs/spec.md 为准，resume.md 只是索引。
发现不一致，告诉我哪里不一致，不要自己选一个信。

我确认之后你再动手。如果 resume.md 缺失或明显过期，先用 10 行重建它，再问我确认。
```

## resume.md 模板（10 行，换项目照抄）

```markdown
# 项目状态（新会话先读这个）

更新: 2026-11-21 16:20
阶段: 点亮 → 已过 L2，卡在 L3
本轮: 实现 spec F3（I2C 重试）已加超时，异常注入还没跑
下一步: 补 F3 的 NACK 注入用例，然后跑 T1
未决: 客户没说报警是声光还是上报（等确认，影响 F4）
决策: 重试 3 次退避 10/50/200ms（理由：沿用旧项目，客户未要求）
坑: L3 寄存器 0x1F 回读总少一位，怀疑 SPI 读位序，未解
指针: docs/spec.md · docs/design.md · .embedded/bringup-log.md
```

## 什么时候更新

三个时机，缺一个就会丢状态：

1. **每轮结束**（提交或停手前）
2. **做了不可逆决定后**（改协议、换方案、砍功能）——理由要写进 `决策:` 行，否则下个会话可能推翻你
3. **下班/切任务前**——这是最容易忘、代价最大的一次

## 三条硬规则

1. **10 行以内**。写不下说明你还没想清楚现在在哪——那就先想清楚再写。
2. **覆盖写，不是追加**。跟 `validation-log.md` 正好相反：日志增长，快照重写。用日志来续接会越读越糊涂。
3. **`未决:` 行必须单独存在**。不写未决，下个会话会替你瞎决定——而它不会告诉你它决定了什么。

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 只记日志不写快照 | 新会话知道出过什么事，不知道下一步 | 两个都写，各司其职 |
| 快照写成日记（"今天调了很久…"） | 新会话读不出状态 | 只写状态、下一步、未决 |
| 快照里写"已完成"但代码没提交 | 新会话以为做完了 | 状态以代码和 git 为准，写完先提交 |
| 未决问题混在正文里 | 会被当成已决策过 | 单独一行 `未决:` |
| 换机器后 resume.md 不见了 | 续接失败 | 它含项目细节，故意不进仓库；换机器就从代码和 spec 重建 |

## 为什么状态必须落文件

对话历史不可靠：可能被压缩、被清空，换工具就没有了（DSH、Claude Code、Codex 各自的会话是分开的）。

文件是唯一跨会话、跨工具都成立的状态载体。这也是为什么这套技能把 `docs/` 和 `.embedded/` 分开放——**能进仓库的进仓库，含细节的留本机**，但都在文件系统里，不依赖某个产品的会话。
